# Reference Resolution

`backend/jewelmind/conversation/references.py` cites this document (and [`380`](380-pronoun-and-implicit-target-resolution.md)) in its module docstring. The whole module is deterministic string matching — no AI call, no fuzzy matching, no vocabulary invented locally.

## Reuse of `TARGET_SYNONYMS`

`references.py` imports exactly one symbol from Design Intent: `from jewelmind.design_intent.vocabulary import TARGET_SYNONYMS`. This is the same synonym table Design Intent's own `normalize_target()` (`design_intent/normalizer.py`) uses to resolve `"the band"`/`"la fascia"` to the canonical target `BAND`. There is deliberately no second, conversation-local word list — a phrase that Design Intent already knows resolves to `BAND` resolves to the identical `BAND` string here, so a turn's `references` and a `DesignIntent`'s `IntentStatement.target` are directly comparable values, never two independently-maintained vocabularies that could quietly drift apart.

## The five functions

### `find_explicit_target(text: str) -> str | None`

Lowercases `text` and checks every key of `TARGET_SYNONYMS`, longest phrase first (`sorted(TARGET_SYNONYMS.keys(), key=len, reverse=True)`), returning the first canonical target matched. Checking longer phrases first is what makes `"oro rosa"` (rose gold) match before a bare `"oro"` (gold) would — both are real keys in the same table, and without the length-descending order the shorter, less specific match could win by accident.

### `find_preserve_target(text: str) -> str | None`

Returns `None` unless `text` contains one of `_PRESERVE_MARKERS` (`"leave"`, `"keep"`, `"lascia"`, `"lasciala"`, `"lascialo"`, `"lasciate"`); if it does, delegates to `find_explicit_target()`. A preserve phrase with no named target (e.g. a bare `"leave it"`) returns `None` here too — [`380`](380-pronoun-and-implicit-target-resolution.md) covers why that case is treated as ambiguous rather than guessed.

### `mentions_material_word(text: str) -> bool`

True if `text` contains any of `_MATERIAL_WORDS`: `gold`, `oro`, `platinum`, `platino`, `silver`, `argento`, `rose gold`, `oro rosa`, `white gold`, `oro bianco`, `yellow gold`, `oro giallo`.

### `mentions_comparative_marker(text: str) -> bool`

True if `text` contains any of `_COMPARATIVE_MARKERS`: `wider`, `narrower`, `bigger`, `smaller`, `larger`, `thicker`, `thinner`, and their Italian equivalents (`più largo`, `più larga`, `più stretto`, `più grande`, `più piccolo`, `più spesso`, `più sottile`), plus bare `wide`/`narrow`.

### `resolve_implicit_target(text, last_referenced_target) -> tuple[str | None, bool]`

The composed resolution function — see [`380`](380-pronoun-and-implicit-target-resolution.md) for its full branch-by-branch logic.

## Real examples

`specs/conversation/v1/test-vectors/reference-resolution-vectors.json`, generated by actually running these functions:

| `text` | `lastReferencedTarget` | `resolvedTarget` | `isAmbiguous` | `preserveTarget` |
|---|---|---|---|---|
| "Allarga la fascia." | `null` | `BAND` | `false` | `null` |
| "Make the stone bolder." | `null` | `STONE` | `false` | `null` |
| "make it wider" | `null` | `null` | `true` | `null` |
| "make it wider" | `BAND` | `BAND` | `false` | `null` |
| "make it rose gold" | `null` | `MATERIAL_APPEARANCE` | `false` | `null` |
| "Make it more classic." | `null` | `null` | `false` | `null` |
| "leave the stone as is" | `null` | `STONE` | `false` | `STONE` |
| "keep the band" | `null` | `BAND` | `false` | `BAND` |

Note the "Make it more classic." row: `resolvedTarget: null` and `isAmbiguous: false` together — a bare pronoun with no comparative marker and no established topic resolves to *nothing structural*, but is explicitly **not** flagged ambiguous. See [`380`](380-pronoun-and-implicit-target-resolution.md) for why that combination is correct rather than contradictory.
