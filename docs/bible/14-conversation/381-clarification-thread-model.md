# Clarification Thread Model

`backend/jewelmind/conversation/clarifications.py` cites this document (and [`382`](382-clarification-answer-resolution.md)) in its module docstring.

## `ClarificationThread` fields

See [`372-conversation-domain-model.md`](372-conversation-domain-model.md) for the full field table. Restated here for the lifecycle functions below: `clarificationId`, `originatingTurnId`, `question`, `target`, `expectedAnswerType`, `allowedChoices`, `required`, `status`, `createdAt`, `resolvedAt`, `answer`.

## Lifecycle functions

All five are pure functions in `clarifications.py` — none mutate a `ClarificationThread` in place (Pydantic models here are treated as immutable snapshots; every "close" operation returns a new instance via `model_copy(update=...)`).

### `open_clarification(turn_id, question, target, expected_answer_type, now, allowed_choices=None, required=True) -> ClarificationThread`

Constructs a fresh thread: `clarificationId=f"clarification-{uuid.uuid4()}"`, `status="OPEN"`, `createdAt=now`, `resolvedAt=None` (implicit, unset). `allowed_choices` defaults to `[]` if not given.

### `try_resolve_answer(thread, raw_answer) -> tuple[str | float | None, bool]`

See [`382`](382-clarification-answer-resolution.md) for the per-type validation rules. Never mutates `thread` — the caller (`service.py::_handle_answer_clarification()`) decides what to do with the `(resolved_value, accepted)` result.

### `close_answered(thread, raw_answer, resolved_value, now) -> ClarificationThread`

`thread.model_copy(update={"status": "ANSWERED", "answer": raw_answer, "resolvedAt": now})`. Note the stored `answer` is the *raw* answer text, not `resolved_value` — the parsed/validated value is threaded separately into the combined text sent to Designer (see [`382`](382-clarification-answer-resolution.md)), while the thread record itself preserves what the user actually typed.

### `cancel(thread, now) -> ClarificationThread`

`thread.model_copy(update={"status": "CANCELLED", "resolvedAt": now})`. Declared and schema-complete, but note `_handle_cancel()` in `service.py` does not call this function — it simply sets `session.pendingClarification = None` directly, discarding the thread object entirely rather than keeping a `CANCELLED`-status record of it. A grep of `backend/tests/` for `clarifications.cancel(` or `clarifications.supersede(` finds no call sites at all — `cancel()` is a real, working function (`clarifications.py` implements it correctly) but it is currently neither invoked by `service.py` nor exercised by any test in the suite. This is an honest gap between the lifecycle module's full capability and how `service.py` actually uses it today, not a claim of test coverage that doesn't exist.

### `supersede(thread, now) -> ClarificationThread`

`thread.model_copy(update={"status": "SUPERSEDED", "resolvedAt": now})`. Same note as `cancel()`: declared and available, with no test call site, but `service.py` never calls it — the only place a proposal is superseded (`_handle_designer_routed()`'s correction-handling branch) supersedes a `ConversationProposal`, not a `ClarificationThread`. No current code path produces a `ClarificationThread` with `status="SUPERSEDED"`.

## The 4 `ExpectedAnswerType` values and their validation

`try_resolve_answer(thread, raw_answer)` branches on `thread.expectedAnswerType`:

| Type | Validation |
|---|---|
| `NUMERIC` | Strips whitespace, lowercases, removes the substring `"mm"`, strips again, then `float(candidate)`. Accepts `"2.7"`, `"2.7mm"`, `"2.7 mm"`. A `ValueError` (non-numeric text) returns `(None, False)` — never a guessed value. |
| `ENUM_CHOICE` | Case-insensitive exact match of the trimmed answer against `thread.allowedChoices`; returns the *original-cased* choice string from the list on a hit, `(None, False)` on no match. No partial or fuzzy matching. |
| `CONFIRMATION` | Lowercased answer checked against two fixed sets: `_CONFIRMATION_YES = {"yes", "y", "si", "sì", "ok", "va bene", "d'accordo"}` and `_CONFIRMATION_NO = {"no", "not really", "niente"}`. Returns `("yes", True)`, `("no", True)`, or `(None, False)`. |
| `FREE_TEXT` | Any non-empty trimmed string is accepted as-is; an empty string returns `(None, False)`. |
