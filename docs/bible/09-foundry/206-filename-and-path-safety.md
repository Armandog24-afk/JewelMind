# Filename and Path Safety

## The real sanitizer

`backend/jewelmind/exporters/filenames.py::sanitize_filename(name, *, default="jewelmind-export")`: collapses any character outside `[A-Za-z0-9._-]` to a single underscore, strips leading `.`/`-`/`_`, falls back to `default` if nothing usable remains, and truncates to 120 characters. Applied to every export's suggested download filename, always derived from `record.definition.project.name` — a user-controlled string — never used to construct a server-side path.

## Real test vectors, generated by running the function during Sprint 7

| Input | Output | Note |
|---|---|---|
| `"My Ring-01.v2"` | `"My_Ring-01.v2"` | Space collapsed to underscore |
| `""` | `"jewelmind-export"` | Falls back to default |
| `"   "` | `"jewelmind-export"` | Whitespace-only also falls back |
| `"..."` | `"jewelmind-export"` | Dots alone strip to nothing, falls back |
| `".hidden"` | does not start with `.` | Leading dot stripped |
| `"-rm -rf"` | does not start with `-` | Leading dash stripped, preventing an option-like filename |
| `"a:b*c?d\"e<f>g|h"` | every Windows-reserved path character replaced | `: * ? " < > \|` all collapse to `_` |
| 500 × `"a"` | truncated to 120 characters | Length cap enforced |

## A real, documented, low-risk gap

**`"CON"` passes through unmodified as `"CON"`.** Windows reserved device names (`CON`, `PRN`, `AUX`, `NUL`, `COM1`–`COM9`, `LPT1`–`LPT9`) are not rewritten by `sanitize_filename()`. This is a genuine gap, confirmed by `backend/tests/test_filenames.py::test_windows_reserved_device_names_pass_through_unmodified`, but it is low-risk: the sanitized string is only ever used as the client-visible `Content-Disposition` suggested filename for a download, never as an actual server-side filesystem path (the real temp file is always named via `tempfile.mkstemp()`, which never uses the user-controlled project name at all — see [`207-temp-file-lifecycle.md`](207-temp-file-lifecycle.md)). A browser saving a file literally named `CON.step` on a Windows client is a client-side inconvenience, not a server vulnerability.

## No internal server path is ever exposed

The value passed to `Content-Disposition` and returned in the JSON/HTML surface is always the sanitized project name plus extension — never the real `tempfile.mkstemp()`-generated path, which stays server-internal for the lifetime of the request (restates FOUNDRY-GOV-011).
