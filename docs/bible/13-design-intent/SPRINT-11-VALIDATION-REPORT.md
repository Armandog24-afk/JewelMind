# Sprint 11 Validation Report

## Documents created

`docs/bible/13-design-intent/README.md` plus `330-intent-governance.md` (18 INTENT-GOV rules), 33 further numbered documents (`331`-`363`), plus this report — 36 files total. 9 new appendices: `intent-vocabulary-catalog.md`, `intent-target-catalog.md`, `intent-relation-catalog.md`, `intent-resolution-catalog.md`, `intent-conflict-catalog.md`, `intent-diagnostic-catalog.md`, `intent-test-case-catalog.md`, `intent-code-mapping.md`, `intent-test-matrix.md` (`JM-BIBLE-A64` through `A72`, continuing from Sprint 10's last appendix, `A63`).

## Schemas created

7 JSON Schemas (Draft 2020-12): `design-intent`, `intent-statement`, `intent-target`, `intent-relation`, `intent-profile`, `intent-resolution`, `intent-diagnostic`. Plus `vocabulary.json`, the controlled-vocabulary source of truth (never containing a CAD/numeric mapping — verified by `backend/tests/test_design_intent_schemas.py::test_vocabulary_file_exists_and_has_no_numeric_cad_mapping`). 7 examples and 6 test-vector files in `specs/design-intent/v1/`, all generated by actually running `build_design_intent()`.

## Canonical intent concepts

**6**: `VISUAL_WEIGHT`, `SIMPLICITY`, `STYLE_TEMPORALITY`, `VISUAL_EMPHASIS`, `PROPORTIONAL_CHARACTER`, `STRUCTURAL_CHARACTER` — each an ordered semantic continuum (`backend/jewelmind/design_intent/vocabulary.py::CATEGORIES`), never a millimeter value or an invented numeric score.

## Canonical intent values

**23** across the 6 continua: `VISUAL_WEIGHT` (DELICATE, LIGHT, BALANCED, SUBSTANTIAL, BOLD — 5), `SIMPLICITY` (MINIMAL, CLEAN, BALANCED, DETAILED, ORNATE — 5), `STYLE_TEMPORALITY` (CLASSIC, TIMELESS, CONTEMPORARY, MODERN — 4), `VISUAL_EMPHASIS` (UNDERSTATED, BALANCED, CENTER_FOCUSED, STATEMENT — 4), `PROPORTIONAL_CHARACTER` (SLIM, BALANCED, BROAD — 3), `STRUCTURAL_CHARACTER` (SOFT, CLEAN, STRONG — 3). Plus 10 canonical targets and 6 relation predicates.

## Supported languages

Italian and English — the same two languages Designer v1 already supports, via hand-authored synonym tables in `vocabulary.py`, deliberately excluding genuinely ambiguous words (e.g. Italian "importante") rather than guessing a classification for them.

## Intent vocabulary implemented

**Yes** — `backend/jewelmind/design_intent/vocabulary.py`, mirrored machine-readably in `specs/design-intent/v1/vocabulary.json`.

## Intent provenance implemented

**Yes** — the full 8-value `IntentProvenance` enum exists in `design_intent/schemas.py`; only `AI_NORMALIZED` is currently produced by the real pipeline (the rest are schema-complete for future stages, the same honest pattern Designer v1 used for `FieldProvenance` in Sprint 10).

## Relative-intent relationships implemented

**Yes** — `IntentRelation` with 6 controlled predicates (`NARROWER_THAN`, `BROADER_THAN`, `DOMINANT_OVER`, `SUBORDINATE_TO`, `DISCREET_RELATIVE_TO`, `BALANCED_WITH`), real extraction and normalization in `normalizer.py::normalize_predicate()`, covered by 6 dedicated `RELATION` corpus cases.

## Conflict representation implemented

**Yes** — `conflicts.py::detect_conflicts()` runs real value-continuum-distance and relation-opposite-predicate detection, producing `EXPLICIT_CONTRADICTION`, `SOFT_TENSION`, `PRIORITY_CONFLICT`, and `TARGET_CONFLICT` (verified live via `specs/design-intent/v1/test-vectors/conflict-vectors.json`, a real generated artifact). `RESOLUTION_CONFLICT` is schema-reserved, not yet produced — a named, honest gap in [`362-design-intent-gap-analysis.md`](362-design-intent-gap-analysis.md).

## Unresolved intent preservation implemented

**Yes** — `DesignIntent.unresolvedDescriptors`, verified by 10 dedicated corpus cases (`UNRESOLVED_DESCRIPTOR`/`UNKNOWN_DESCRIPTOR`) and the exact required user-facing copy ("has been preserved as design intent...") in `DesignerPanel.tsx`.

## Designer technical/intent separation implemented

**Yes** — `RawDesignerResponse` now carries `designIntentStatements`/`designIntentRelations` alongside `proposedCanonicalValues`, processed through entirely separate code paths in `service.py::_build_proposal()`; verified by `test_designer_intent_integration.py::TestDesignerTechnicalVsIntentSeparation`.

## Studio intent review implemented

**Yes** — `DesignerPanel.tsx` renders a dedicated "Design intent" section (separate from "JewelMind understood"), a "Conflicting intent" section, unresolved-descriptor messaging with the exact required copy, a persistent compact intent summary with per-item removal (section 48), and Apply/Cancel actions. **Known, deliberate simplification, consistent with Sprint 10's own precedent**: no separate "edit value" control per statement beyond removal — editing a statement's value means describing it again in a follow-up request, since `ConfigurationPanel` (the parameter editor) has no analog for aesthetic intent to edit inline. Documented in [`357-studio-intent-review.md`](357-studio-intent-review.md) and listed in [`362-design-intent-gap-analysis.md`](362-design-intent-gap-analysis.md).

## Arbitrary subjective-to-numeric mappings found

**0** — audited across every file in `backend/jewelmind/design_intent/` and every field-processing branch in `backend/jewelmind/designer/service.py`; no code path ever assigns a JDL numeric field from an `IntentStatement`.

## Arbitrary subjective-to-numeric mappings remaining

**0** — same audit; this is the deliberately correct end state for v1, not a partial result (see `349-deterministic-resolution-policy.md`).

## Intent-only changes correctly preserve current model

**Yes** — `backend/jewelmind/designer/service.py` now diffs every proposal against whatever `currentJDL` the caller actually has loaded (not just for MODIFY), and `DesignerPanel.tsx::handleApply()` only calls `applyDesignerProposal()` (the JDL/staleness path) when `proposal.diff.some(d => d.changed)` is true — applying a pure-intent proposal calls only `useDesignIntentStore.applyIntent()`, which has zero connection to `useProjectStore.isStale`. Verified by two dedicated frontend tests: `'does not mark the model stale when the proposal contains only design intent'` and `'does mark the model stale when the proposal contains a real technical change'`.

## Deterministic corpus cases

**89** natural-language corpus cases in `backend/tests/test_design_intent_corpus.py` (well above the "at least 60 if practical" target), covering descriptor extraction, normalization, target resolution, relations, unresolved/unknown descriptors, the mandatory `NO_ARBITRARY_NUMERIC_MAPPING` category (10 cases), multilingual convergence, and conflicts.
