# Appendix: API Inventory

Generated by inspecting `backend/jewelmind/api/routes.py` directly. Full
request/response shapes: `docs/api.md`.

| Endpoint | Method | Input | Output | Validation behavior | Error behavior | File |
|---|---|---|---|---|---|---|
| `/api/health` | GET | none | `{status, service, version, cadEngine, cadEngineReady, cadEngineError}` | n/a | Returns HTTP 200 if the CAD engine is ready, HTTP 503 with `cadEngineReady: false` and an error message otherwise. Never raises. | `routes.py::health` |
| `/api/models/validate` | POST | `JewelryDefinition` | `{results: ValidationResult[], hasErrors: bool}` | Runs all sixteen rules directly against `validation/engine.py`; does not touch `model_service` or CadQuery. | Malformed body -> 422 `REQUEST_VALIDATION_ERROR`. Never fails due to CAD engine state. | `routes.py::validate_model` |
| `/api/models/generate` | POST | `JewelryDefinition` | `{modelId, definitionHash, validation, metadata, previewComponents, warnings, generatedAt}` | Re-validates authoritatively before building geometry. | Validation errors -> 422 `VALIDATION_BLOCKED`. CAD engine unavailable -> 503 `CAD_ENGINE_UNAVAILABLE`. Unexpected geometry failure -> 500 `MODEL_GENERATION_FAILED`. | `routes.py::generate_model` |
| `/api/models/{modelId}/metadata` | GET | path param `modelId` | `ModelMetadataResponse` (same metadata shape as generate, without regenerating) | n/a (read of cached record) | Unknown `modelId` -> 404 `MODEL_NOT_FOUND`. | `routes.py::model_metadata` |
| `/api/models/{modelId}/preview/{componentName}` | GET | path params `modelId`, `componentName` | Binary STL file (`model/stl`) | n/a | Unknown model or component with no geometry -> 404 `MODEL_NOT_FOUND`. | `routes.py::model_preview` |
| `/api/models/export/step` | POST | `{modelId, includeStoneReference?}` | Real STEP file, `Content-Disposition: attachment` | Operates on an already-generated (already-validated) model only. | Unknown `modelId` -> 404 `MODEL_NOT_FOUND`. Export failure -> 500 `STEP_EXPORT_FAILED`. | `routes.py::export_step_route` |
| `/api/models/export/stl` | POST | `{modelId, includeStoneReference?, meshTolerance?, angularTolerance?}` | Real STL file, `Content-Disposition: attachment` | `meshTolerance`/`angularTolerance`, if provided, must be finite and `> 0` (`api/schemas.py::ExportStlRequest`). | Invalid tolerance -> 422. Unknown `modelId` -> 404. Export failure -> 500 `STL_EXPORT_FAILED`. | `routes.py::export_stl_route` |
| `/api/models/export/json` | POST | `{modelId}` | Canonical `JewelryDefinition` JSON, `Content-Disposition: attachment` | n/a | Unknown `modelId` -> 404 `MODEL_NOT_FOUND`. | `routes.py::export_json_route` |
| `/api/models/specification` | POST | `{modelId}` | Markdown technical specification, `Content-Disposition: attachment` | n/a | Unknown `modelId` -> 404 `MODEL_NOT_FOUND`. | `routes.py::specification_route` |

## Error code reference

| Code | HTTP status | Raised by |
|---|---|---|
| `VALIDATION_BLOCKED` | 422 | `services/model_service.py::generate` when validation errors exist |
| `REQUEST_VALIDATION_ERROR` | 422 | FastAPI/Pydantic request-body validation failure |
| `MODEL_NOT_FOUND` | 404 | `services/model_service.py::get_record` / `preview_file` for an unknown `modelId` |
| `MODEL_GENERATION_FAILED` | 500 | `api/routes.py::generate_model` for any unexpected geometry-generation exception |
| `STEP_EXPORT_FAILED` | 500 | `api/routes.py::export_step_route` for any unexpected STEP-export exception |
| `STL_EXPORT_FAILED` | 500 | `api/routes.py::export_stl_route` for any unexpected STL-export exception |
| `CAD_ENGINE_UNAVAILABLE` | 503 | `api/routes.py::_get_model_service` when the geometry/CadQuery import chain fails |
| `INTERNAL_ERROR` | 500 | `api/app.py`'s catch-all handler for any other uncaught exception |

Every error response uses the shared envelope:
`{"error": {"code", "message", "requestId", "details"}}` — see
`backend/jewelmind/api/errors.py` and `app.py`.

## Not covered by this inventory

Interactive documentation (Swagger UI at `/docs`, ReDoc at `/redoc`) is
generated automatically by FastAPI from the same route definitions and is
not separately listed here.
