# Vision v1 — Machine-Readable Specification

The machine-readable half of Vision. The narrative, architecture, and contract half lives in [`docs/bible/10-vision/`](../../../docs/bible/10-vision/README.md); start there for context.

## What Vision is

Vision is the visual-output layer: the boundary between an already-generated Atlas geometry and what a person sees — a Technical inspection view and a Presentation display view, plus a client-side PNG capture of the latter. **Unlike every prior sprint's specification, Vision v1's schemas describe a real, newly-shipped feature set**, not a target architecture layered over pre-existing behavior — the Technical/Presentation split, camera-preset system, material system, and image capture were all implemented in this same Sprint.

## No fabricated measurements

Every numeric value in `examples/` and `test-vectors/` — camera positions, ground Y, material colors/parameters — was obtained by running the real `frontend/src/vision/*.ts` modules (via `node --experimental-strip-types`) against the default solitaire's real, previously-verified bounding box (`definitionHash: 355ddca57e7e49ad`, first established in Sprint 5/6/7's own examples), not estimated or hand-typed.

## How these files are validated

`backend/tests/test_vision_schemas.py` (added in Sprint 8) validates all 6 schemas and all 6 examples against their respective schemas using the same `jsonschema` library already used for every prior sprint's specs — chosen over a frontend-side validator so this repository has exactly one JSON-Schema-validation toolchain, not two.
