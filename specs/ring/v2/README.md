# Ring Architecture v2 — machine-readable specifications

The Ring-category half of [`docs/bible/18-ring-architecture/`](../../../docs/bible/18-ring-architecture/README.md). Describes `RingDefinition` v2 — a domain contract **underneath** JDL, not a second canonical JDL schema. The authoritative external input format remains `backend/jewelmind/domain/schema.py` (mirrored at `shared/types/jewelry-definition.ts`); everything here describes the internal, composable model `ring_definition_from_jdl()` builds from a real `JewelryDefinition`.

## Authority

| Concern | Authoritative source |
|---|---|
| External JDL input shape | `backend/jewelmind/domain/schema.py` / `specs/jdl/v1/` |
| Business-rule validation | `backend/jewelmind/validation/engine.py` / `specs/forge/v1/` |
| Internal ring composition | **This directory** |
| Real generated geometry | `backend/jewelmind/geometry/` / `specs/atlas/v1/` |

## Schemas

| File | Describes |
|---|---|
| `ring-definition.schema.json` | The composed `RingDefinition` v2 — family, sizing, shank, shoulders, head, stone arrangement, setting. |
| `ring-sizing.schema.json` | `RingSizing` — 1:1 mapping from `JewelryDefinition.ring`. |
| `shank-definition.schema.json` | `ShankDefinition` — CURRENT: uniform plain shank only. |
| `shoulder-definition.schema.json` | `ShoulderDefinition` — IMPLICIT/PARTIAL: no independent geometry exists today. |
| `head-definition.schema.json` | `RingHeadDefinition` — PARTIAL: basket support height only; prong data lives in `setting` (see `ring-definition.schema.json`). |
| `stone-arrangement.schema.json` | `StoneArrangementDefinition` — CURRENT: `SINGLE_CENTER` only. |
| `ring-component.schema.json` | Maps an architectural composition node (shank/head/stoneArrangement) to real Atlas component IDs. |
| `ring-family.schema.json` | The recognized ring-family vocabulary — only `solitaire` is CURRENT. |

## Examples

`examples/` holds 3 real `RingDefinition` v2 objects, generated by running the real `ring_definition_from_jdl()` adapter against real `JewelryDefinition` inputs (never hand-invented).

## Test vectors

`test-vectors/` holds 4 files, generated from real code:

| File | Demonstrates |
|---|---|
| `category-boundary-vectors.json` | The generic category dispatch mechanism rejecting an unsupported category cleanly. |
| `solitaire-migration-vectors.json` | The field-by-field JDL → RingDefinition mapping for a real solitaire definition. |
| `component-composition-vectors.json` | The CURRENT ring component graph (which real Atlas components each architectural node groups). |
| `category-extension-vectors.json` | The test-only dummy category dispatching through the same generic function as `ring` — proof of extensibility, never a production capability. |
