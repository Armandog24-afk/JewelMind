# Forge Rule System v1 — Machine-Readable Specification

This directory is the machine-readable half of the JewelMind Forge Rule System v1. The narrative, governance, and lifecycle half lives in [`docs/bible/06-forge/`](../../../docs/bible/06-forge/README.md); start there for context.

## What Forge is

Forge is the authoritative repository of jewelry-domain rules — the formal model behind the 16 rules currently implemented in `backend/jewelmind/validation/rules.py`/`engine.py`, plus 5 additional cross-cutting rules (schema, safety, geometry-inspection, export-precondition) newly given stable IDs in this Sprint so every category in the classification model has a real, current example. **Forge v1 is a specification and classification layer over the existing validation engine — it is not a new runtime system.** No new rule-evaluation code was written; `backend/jewelmind/validation/engine.py` remains the actual authority.

## Files

| File | Purpose |
|---|---|
| [`rule.schema.json`](rule.schema.json) | Structural schema for a full `ForgeRule` definition |
| [`rule-result.schema.json`](rule-result.schema.json) | Structural schema for a `ForgeRuleResult` diagnostic |
| [`rule-context.schema.json`](rule-context.schema.json) | Structural schema for a `ForgeEvaluationContext` |
| [`rule-registry.schema.json`](rule-registry.schema.json) | Structural schema for the aggregate rule registry |
| [`current-rule-registry.json`](current-rule-registry.json) | The actual registry: all 21 currently-existing rules, generated by inspecting the real codebase |
| [`examples/valid/`](examples/valid/) | 2 complete, schema-valid `ForgeRule` definitions |
| [`examples/invalid/`](examples/invalid/) | 4 definitions, each invalid for one documented reason |
| [`test-vectors/`](test-vectors/) | Evaluation, severity, precedence, and provenance vectors, generated from the real `validation/engine.py` |

## Rule count summary (from `current-rule-registry.json`)

- **21 total rules**: 16 pre-existing jewelry-domain rules (`JM-*`, unchanged, not renamed) + 5 newly-named cross-cutting rules (`FORGE-SCHEMA-001`, `FORGE-SAFETY-001`, `FORGE-SAFETY-002`, `FORGE-GEOM-001`, `FORGE-EXPORT-001`) that already existed as code behavior but had no stable rule ID before this Sprint.
- **Professionally validated rules: 0.** Every rule's `professionalValidationStatus` is `preliminary` or `not_required` — see [`docs/bible/06-forge/103-professional-validation-lifecycle.md`](../../../docs/bible/06-forge/103-professional-validation-lifecycle.md) and Sprint 4's governing instruction: professional validation is never invented.

## How these files are validated

`backend/tests/test_forge_registry.py` (added in Sprint 4) validates `current-rule-registry.json` against `rule-registry.schema.json`, validates every example against `rule.schema.json`, confirms every invalid example fails for its documented reason, and cross-checks every `JM-*` entry's severity against a live run of `validate_definition()`.
